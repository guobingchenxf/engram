# Stage 4 Report: Depth and Differentiation

Date: 2026-11-05

## 1. Graph memory

Added an entity index and graph candidate expansion:

- `memory_entities(memory_id, entity)` table;
- `SQLiteMemoryStore.sync_entities()` on insert/update;
- `SQLiteMemoryStore.find_by_entities()` for entity lookup;
- retrieval merges graph candidates with vector/BM25 candidates;
- graph score = query-entity overlap / query entities, added with
  `MEMORY_GRAPH_WEIGHT` (default 0.15);
- graph-only candidates can pass the relevance threshold when the entity overlaps;
- `SearchHit.graph` exposes the graph contribution.

Tests: `tests/test_graph.py` covers graph retrieval, graph disable, and direct
entity lookup.

## 2. Red-team

Added `src/engram/redteam.py` with 12 cases across:

- prompt injection (English/Chinese/web);
- data exfiltration;
- permission abuse;
- memory poisoning via tool sources;
- secrets;
- PII (phone/email);
- untrusted episodic vs semantic writes;
- benign preference.

Run:

```bash
python -m engram.cli redteam
```

Result: **12/12 pass**. See [REDTEAM.md](REDTEAM.md).

## 3. LLM judge

Added `src/engram/judge.py`:

- `LLMJudge.judge()` with rubric prompt and heuristic fallback;
- `judge_pairwise()` with A/B position swapping;
- `length_bias_probe()` with padded answers;
- JSON parsing and safe fallback when the judge provider fails.

Tests: `tests/test_judge.py` covers heuristic scoring, JSON parsing, position
bias detection, and length probing. The LLM path is tested with a fake client;
a real provider smoke test still requires an API key.

## 4. Visualization

Added `src/engram/viewer.py` with two self-contained HTML views:

**Trace viewer**

- dark HTML page with event summary, filter box, raw payload per row;
- `GET /v1/trace/view` (respects API-key auth);
- `python -m engram.cli trace-view --out reports/trace.html`.

**Benchmark dashboard**

- summary cards (memory/baseline pass rate, scenarios, checks, avg tokens);
- condition bars for memory, full-history and all ablations;
- per-category bars, pass/fail scenario grid, failure details;
- generated by `python -m engram.cli bench --html reports/benchmark.html`;
- screenshot: `docs/assets/benchmark-dashboard.png`.

Tests: `tests/test_viewer.py` covers trace rendering, benchmark HTML and the API
endpoint.

## 5. Deep Research integration

Added `src/engram/integrations/deep_research.py`:

- `MemoryToolbox`: `search_context`, `search`, `write`, `tools()`;
- `DeepResearchAgent`: retrieve → plan subquestions → search → synthesize →
  write conclusion;
- pluggable `searcher` callback for web search or the P0 harness;
- example: `examples/deep_research_memory.py`.

Tests: `tests/test_integration.py` covers toolbox tools, conclusion persistence,
and an external searcher.

## 7. Honest gaps

- Real embedding provider smoke test still needs an API key; `vector_only` /
  `no_rerank` cannot be meaningfully differentiated with hash embeddings.
- Graph memory is an entity index + candidate expansion, not a full graph
  database with multi-hop traversal.
- Red-team is a heuristic baseline; end-to-end indirect injection through tool
  output is not covered.
- LLM judge is tested with a fake client; position/length calibration on a real
  judge is not measured.
- No external benchmark (LoCoMo / LongMemEval / MemoryAgentBench) yet.
- No rate limiting, Postgres/pgvector, or encryption at rest.
